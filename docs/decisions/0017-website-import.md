# 0017 — Website import

Status: accepted.

## Context

The owner wants "website in apps": a shop, portfolio or blog someone already has should become a
Smudge post that opens in the in-app page sheet, without them rebuilding it. Showing the live site
in a frame already exists (post buttons with a `url`), but many sites refuse to be framed, the page
can change or vanish, and it does not look like it belongs in Smudge.

## Decision

- **Copy once, then it's a Smudge page.** Create → **Import a website** → paste a link. The server
  reads the page once and extracts title, description, theme colour, headings, paragraphs, quotes,
  photos and products (JSON-LD `Product`, or a name followed by a price). The person edits it
  (kind, title, intro, cover, photos, products, text) beside a live preview and publishes it as an
  ordinary v2 post. It opens in the page sheet like any post made in Smudge.
- **Three layouts.** Article, Shop or Portfolio, guessed from what was found (three or more
  products is a shop; six or more photos with little text is a portfolio) and switchable.
- **Nothing executable comes along.** The post is generated by `buildImportedPage` from plain text
  and asset ids only: no script, no site HTML, no remote URLs. Photos are downloaded, re-encoded to
  WebP and stored as the importer's assets, so the post works offline in the runtime sandbox.
- **Server-side fetching is treated as hostile.** Fetching a URL a user typed is the classic way
  into a server's private network (SSRF). See contracts.md for the rules: public addresses only,
  connection pinned to the checked address, redirects re-checked, size and time limits, rate limit.
- **Permission, not ownership proof (yet).** The person must confirm "This is my site, or I have
  permission to copy it." The post shows "Imported from {host} · Visit original site" so the origin
  is visible. Verifying ownership (a meta tag or DNS record) is left for later.
- **sharp** is a direct dependency, for decoding untrusted images safely and keeping photos small
  (assets are inlined as data URLs in the sandboxed frame).

## Consequences

- Sites that build their content with JavaScript come through thin; the editor says so and the
  person can fill in the rest.
- An import is a snapshot. Changes to the original site don't reach the post.
- `source` is a claim by the importer. Moderation handles misuse through the usual report flow.
- Tests use a local trial site (`tests/fixtures/sites`) allowed via `FORMA_IMPORT_ALLOW_HOSTS`;
  nothing in the test suite reaches the internet.
